## 已部署

```text
A1/A2/A3/S1/S2/S3
  journal / 白名单日志文件 / Kubernetes CRI 文件
       ↓ 本机 Vector：字段白名单、脱敏、截断、限流
       ↓ 每节点 512MiB 磁盘缓冲，满时丢新日志
       └──── HTTPS + 独立 INSERT 账号 ────→ S3:8443
                                             ↓
                                  crawler_logs.events
                                三天 TTL + 周期容量清理
                                             ↑
                                Grafana 双副本 / SELECT 账号
```

六台 Vector 0.58.0（正式版本，非 GitHub latest 中的 vdev 工具版本）；Grafana 官方签名插件 4.21.3。两份制品均核对官方 SHA256，记录在 `ops/logging/releases.json`。新增 TLS CA、每节点账号、只读查询账号；来源 IP 和 NetworkPolicy 均有限制。云防火墙 S3 TCP 8443 / `10.4.4.0/22` 已由用户配置并复测成功。

没有引入数据库服务器、SQLite、Loki 或业务 Collector。S3 原有 `crawler_analytics` 保留；新日志数据库独立授权。Grafana 仍使用现有 PG 保存自身配置；其原账号和入口不变。

1. 六节点分别写入 systemd 测试日志，中央查询得到全部六个节点及正确来源。明文测试 password/token 未进入正文，替换为 REDACTED。
2. A2 临时容器输出实际 CRI 日志，中央记录的 node/namespace/pod/container 正确，测试密码已脱敏；Pod 已删除。
3. INSERT 账号可认证但无法 SELECT 日志表；Grafana SELECT 账号无法 INSERT，也无法读取另一个临时测试表；临时表已删除。无可信 CA 的 HTTPS 客户端证书验证失败。
4. Grafana 官方数据源 health=OK，实际 `/api/ds/query` 返回日志帧；日志数量和明细两块面板的真实 SQL（含时间宏）均返回 HTTP 200。没有只以 Pod Ready 代替插件可用性验证。
5. 仅阻断 A3 主机到 S3:8443 的日志路径，期间注入 12 条日志并重启 Vector。阻断阶段约 **66.13 秒**，kubelet/containerd 保持 active，三 Kubernetes 节点 Ready。恢复后 **10.95 秒**收到 12 条唯一记录，本次观察到重复 **0**。这不是整机断电、长时间离线或 exactly-once 证明。
6. 安装四分钟自动救援定时器，finally 删除专用 OUTPUT 跳转和链、停止救援 timer。`/run` 在现场禁止直接执行文件，恢复脚本通过 `/bin/sh` 运行；最初定时器创建失败发生在注入网络故障之前，修正后演练完成。
7. 独立极小**内存**缓冲的 drop_newest 测试向不可用 HTTP 接收端投入 4,000 条小事件；测试进程写入耗时 0.013 秒，观察到丢弃计数，Vector 仍运行。没有填满线上磁盘缓冲或做生产压力测试。另有真实节点阻断/重启补传验证，两者覆盖不同边界。
8. 五组实际 Vector/VRL 测试覆盖凭据脱敏、字段白名单、长正文截断与 CRI 片段边界；五组保留策略测试覆盖超期、容量、磁盘压力、分区输入保护及避免提前清理。
9. 新日志指标/规则加入原监控：心跳新鲜度、缓冲量、错误/丢弃计数、容量和清理新鲜度。共 40 条规则通过 promtool 校验，既有规则测试通过。终验六节点日志心跳在 180 秒内，全部本地 collector 成功，八个 Argo 应用 Synced/Healthy；剩余活动告警只有原有 Seaweed 持续备份待办。

实现中修正：Vector 0.58 默认不展开环境变量，初次认证因占位符被原样发送而失败；现改为安装时结构化写入 root:0600 私有配置，未开启危险插值。初次安装阶段被永久认证错误拒绝的日志没有承诺补回。Grafana ClickHouse 驱动需要可调整查询超时，账号保持 readonly=1，仅允许 max_execution_time 在 1–60 秒内变化；没有扩大写权限。

## 容量与恢复边界

- 日志为可丢失诊断数据，不替代业务 Kafka/Outbox。网络/接收端故障只影响日志流；短时补传已验证，长时故障超过本地缓冲或源日志轮转仍可能丢失。
- 单行输入 32KiB，正文最多 4096 字符；每节点非心跳 200 条/10 秒。CRI P 片段不重组、DEBUG/历史等未承诺全量完整归档。日志等级目前从正文关键字推断，不等于所有服务的权威严重级别。
- 按 UTC 小时分区、三天 TTL；每五分钟检查活跃压缩日志量，超过 2GiB 清到约 1.5GiB。系统盘可用低于 15% 时可删除这张派生日志表的全部分区。年龄与容量以先到者为准，可能不足三天。
- 周期阈值不是硬磁盘配额；临时文件、非活跃 parts 和写入窗口有额外占用。S3 单机/系统盘边界仍在，不满足独立磁盘或自动日志存储故障切换。
- 只做有限模式脱敏，不能推断任意未标识秘密；业务应用仍不得直接打印密码、认证头或 Cookie。
- 日志数据不纳入现有 crawler_analytics 日备份。配置、SQL、凭据、TLS 和 Grafana 配置进入现有加密控制面/PG 备份；插件和 Vector 从固定版本/校验值重建。

操作与重建见 `ops/logging/README.md`。Grafana 原入口进入“基础设施 / 爬虫平台 · 集中日志”，按服务器、服务、时间和内容检索。下一项为内部通信认证、权限与加密的分阶段收尾；外围综合验收、Seaweed 持续备份等仍待，业务功能开发未恢复。
